# AIチャット（レポートの修正）設計方針

既存システムの詳細画面にあるものと同じ位置づけの機能を作る。
ただし既存は観測した限り**質問応答のみ**で、レポートを書き換える導線は見当たらなかった。
「修正を加えられる」という要件を満たすには、書き換えを前提にした設計が要る。

## 何が問題になるか

このアプリは生成した原稿を必ず法令ガードレールに通している。

- `lib/guardrail.ts` — 辞書（景表法・薬機法・医療広告GL・金商法）＋ AI の2段
- `lib/copy.ts` の生成物、`lib/ad-ops.ts` の見出し・説明文がすべて通っている

チャットで原稿を書き換えられるようにすると、**書き換えた箇所だけ検査を通っていない状態**になる。
医療・美容・金融の商材では、そこが事故になる。実際に ib-clinic.jp の生成結果では
「痛くない」（医療広告GL）「永久保証で安心」「最短1日で理想の白い歯」が検出されている。
チャットで「もっと強い言葉にして」と言えば、同じ表現が簡単に戻ってくる。

## 決めたこと

**1. 書き換えた内容は必ずガードレールを再通過させる**

チャットが原稿を差し替えるときは、差し替え後のテキストを `checkGuard()` に通す。
`high` が出たら差し替えを行わず、チャット上で「この表現は出せません」と理由と言い換え案を返す。
`medium` は差し替えるが、レポート上に指摘を付けたまま残す。

**2. 書き換えられる範囲を限定する**

チャットから触れるのは「文言」だけにする。以下は触らせない。

| 触れる | 触れない |
|---|---|
| コピー、見出し、説明文、LPO の指摘文 | サイトスキャンの実測値 |
| 訴求軸の説明 | セキュリティヘッダーの合否 |
| 施策の書き方 | MEO のスコアと順位 |
| | Search Console / GA4 の数値 |
| | 検索サジェストの取得結果 |

実測値をチャットで書き換えられると、このアプリの前提（計測していないことを断定しない）が崩れる。
「MEOスコアを80にして」が通ってしまう作りにはしない。

**3. 何を変えたか残す**

差し替えは版として保存し、レポート上で「AIチャットで修正」と分かるようにする。
元に戻せるようにする。誰が見ても、AI が生成した初版と人が直した箇所の区別がつく状態にする。

**4. 文字数は書き換え後も数える**

見出し15文字・説明文45文字の上限は `adWidth()` で数え直す。
超えていたら差し替えず、短くした案を返す。

## 実装の順序

1. チャットの器（右側モーダル・履歴の保存）… 実装済み
2. 質問応答（レポートを文脈として渡すだけ。書き換えなし）… 実装済み
3. 書き換え（対象の指定 → ガードレール再通過 → 版として保存）… 実装済み

## 3の実装メモ

- 書き換えられる文言には短いID（C1-1 / A1-2-H3）を振り、文脈に一覧で渡す。
  AI に配列の添字を数えさせない
- 書き換えは `edit_copy` ツール経由のみ。会話文に新しい原稿を書かせない
- 差し替え前に、文字数 → ガードレールの順で検査する。
  high が出たら差し替えず、理由と言い換え案をツールの結果として返す。
  AI はそれを読んで言い換えを再提案できる
- 1件直したら、そのコピー全体・広告運用設計全体で判定し直す。
  1行だけ直しても他の行が赤なら赤のまま
- 変更は `report_edits` に前後の文言ごと残す
